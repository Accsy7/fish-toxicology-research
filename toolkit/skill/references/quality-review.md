# 质量检查

## 内容复核

从原文和计算记录检查正式分析，再回读最终工作簿与网页。重点核对会改变机制解释、风险比较和选物的内容：

| 对象 | 核对重点 |
|---|---|
| 物质与蛋白 | 研究对象、序列版本、功能注释及跨物种对应是否归属正确 |
| 实验观察 | 物质、条件、终点、单位、实际结果与来源是否对应；多物质研究分别归属 |
| 计算与解释 | 实际执行范围、参数和结果是否支持所写判断；观察到解释之间增加了什么推导 |
| 比较与选物 | 全范围是否得到实际分析；相反结果、条件变化和替代物是否会改变决定 |
| 实验问题 | 所测结果能更新哪项判断；是否覆盖拟讨论的机制和成员 |
| 最终交付 | 字段职责、数值、来源、图注与正式分析一致，全部工作表和网页实际可读 |

发现归属、映射或推导错误时，扩查同类记录，修正原始输入或正式分析后统一导出。修订另存版本，审核记录写明问题位置、影响范围、处理结果、实际复核者及读取材料。独立复核状态按实际参与者登记。

## 工具检查

完整研究使用[完成记录](../assets/completion-record.json)关联分析、审核和交付文件，并运行：

```text
python <skill目录>/scripts/check_completion.py <课题输入.json> <完成记录.json>
```

完成记录的 `analysis:{path,sha256}` 绑定本次正式分析。`content_review` 与各 `checks` 中的 `record_file / sha256` 指向实际核查文件。内容复核使用渲染输入说明中的 `publication_review`；交付检查使用 `validation_record`，含相同的 `project_id / analysis_version / publication_sha256`、实际 `reviewer / findings` 及本次核查的 `checks` 名称数组。脚本核对内容绑定、范围和记录类型；复核者对照原文与导出文件填写具体判断。窄范围修订只重核受影响内容，并将继续适用的核查项关联到新分析。

修改程序时，以实际问题设置回归检查，例如错误来源编号、复核记录串题、字段错位、损坏文件或错误完成状态。程序结果、内容复核和格式检查分别记录。完整哈希、执行日志及修订经过存核查资料。
